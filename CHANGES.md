# Изменения документации

## Что изменилось

Документация упрощена до двух основных файлов:

### 1. RFC1-monorepo.md
RFC-документ с предложением перехода на монорепозиторий:
- Описание 4 пакетов
- Структура проекта
- Зависимости между пакетами
- Инструменты (pnpm, changesets, vite)
- Версионирование

### 2. CTONEW1-instruction.md
Пошаговая инструкция для агента CTO.new:
- 8 этапов реализации
- Конкретные команды bash
- Примеры кода для новых файлов
- Проверочный список
- Troubleshooting

### 3. monorepo-examples/
Готовые конфигурационные файлы (без изменений)

## Что удалено

- Оценки размеров бандлов
- Migration guide (нет обратной совместимости)
- Сроки разработки
- Спекуляции о пользователях и сценариях
- Избыточные диаграммы и псевдографика
- Множественные документы (было ~10, стало 2)

## Структура документов

```
README.md                           → ссылки на RFC и инструкцию
RFC1-monorepo.md                    → предложение в формате RFC
CTONEW1-instruction.md              → инструкция для агента
monorepo-examples/                  → готовые конфигурации
  ├── pnpm-workspace.yaml
  ├── root-package.json
  ├── tsconfig.base.json
  ├── packages/
  │   ├── core/package.json + vite.config.ts
  │   ├── prosemirror/package.json
  │   ├── vanillajs/package.json + vite.config.ts
  │   └── demo/package.json
  └── .github-workflows-*.yml
```

## Принципы упрощения

1. **Только факты** - нет спекуляций о пользователях, сроках, размерах
2. **Конкретность** - команды, код, конфигурации
3. **Минимум документов** - RFC + инструкция вместо 10+ файлов
4. **Без избыточности** - нет migration guide (разработка в рамках major версии)
5. **Практичность** - фокус на реализацию, а не планирование
